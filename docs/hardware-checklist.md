# Hardware checklist

Run on the console before trusting a build. Tick each box only when the expected result happened.

1. [ ] Back up `sdmc:/config/nx-discord-rpc/` to the PC. Expected: a copy of `config.ini` (if any) exists off the console.
2. [ ] Delete `api_key` and `username` from `config.ini`, and `api_key.txt`. Copy `out/` to the SD card and reboot. Expected: the console boots normally.
3. [ ] Open the app from the Album or a title takeover. Expected: tabs Status, Settings, Account, About; the Status footer says "Not linked. Open Account".
4. [ ] Check the special characters in the app (Switch shared font): the ellipsis in "Requesting a code…" (Account, while linking) and in "Unlinking…", the middle dot in "Linked as <name> · relay OK" (Status, once linked). Expected: no boxes or question marks.
5. [ ] Account tab: start a link, scan the QR code. Expected: the relay page opens, the code matches the one on the console.
6. [ ] Enter the code on the phone. Expected: the app shows the linked Discord username within a few seconds and Discord shows the presence.
7. [ ] Wait at least a minute after the link, then read the `Heap:` lines in `sdmc:/config/nx-discord-rpc/log.txt` (one per minute). Expected: "KB in use" stays well under the 1024 KB heap, with no steady growth from one line to the next.
8. [ ] Start a second link or press the link button repeatedly. Expected: no second request while one is pending; if the relay rate limit (10 per hour) is hit, a rate limit message with a wait time appears.
9. [ ] Start a link, then put the console to sleep and wake it. Expected: the link screen says "Link interrupted", not stuck on the code.
10. [ ] Unlink from the Account tab, then link again. Expected: Discord presence disappears after unlink; the second link works and the username returns.
11. [ ] Turn Wi-Fi off and unlink. Expected: within a few seconds, a dialog offering "Forget locally"; choosing it clears the key and username on the console.
12. [ ] With Wi-Fi still off, start a link. Expected: within a few seconds, "Link failed" with "Could not reach the relay. Check the console's connection." and a Retry button. Then turn Wi-Fi on, press Retry and finish the link.
13. [ ] In a game, open the app. Expected: the Status card shows the real game icon and name (matching the NACP icon).
14. [ ] At the HOME Menu, open the app. Expected: the Status card shows the neutral glyph, not a game icon.
15. [ ] Settings tab: toggle each setting (Enabled, Private mode, Show firmware version, Show HOME Menu, Debug log). Expected: the Status tab reflects it within about 1 s; Discord within about 5 s.
16. [ ] Open the overlay in game (Tesla Menu or Ultrahand). Expected: it opens and shows the toggles Enabled, Private mode, This game, Show firmware and Show HOME Menu (no Debug log). The presence line shows the middle dot between the game and its details, and ends with an ellipsis when it is too long for the overlay; both render correctly (Tesla font).
17. [ ] Change a toggle in the app, then look at the overlay, and the reverse. Expected: the other side reflects the change within about 1 s.
18. [ ] Change settings from the overlay, wait 3 s, reboot. Expected: `config.ini` holds the changes and they are still set after reboot.
19. [ ] Remove `atmosphere/contents/4200000000D15C0D/flags/boot2.flag`, reboot, open the app, then the overlay. Expected: the app shows at once a blocking screen saying "NX Discord RPC is not running.", whose only action is Start now; the overlay says it too, without hanging or crashing.
20. [ ] Restore `boot2.flag`, reboot. Expected: the app and overlay work again.
21. [ ] Presence still behaves as before: a game shows its title with elapsed time; HOME shows nothing unless "Show HOME Menu" is on; private mode shows "Playing a game"; no upload or request happens in private mode or at HOME.
22. [ ] Sleep on the dock for several minutes, with background wakes. Expected: nothing is sent while asleep; presence resumes after a real wake.
23. [ ] Restart the relay while playing. Expected: the sysmodule recovers on its own and the presence returns.
24. [ ] Check `log.txt`. Expected: no key or admin key appears in it.
25. [ ] Link a Discord account that has a custom avatar. Expected: the Account tab shows the picture within a few seconds of the "Linked as" line.
26. [ ] On a console that was already linked before this version, reboot and open the Account tab. Expected: the picture appears once the sysmodule has read the profile at boot.
27. [ ] Break the link (revoke NX RPC in Discord, User Settings > Authorized Apps) or turn Wi-Fi off, then reopen the Account tab. Expected: the picture stays.
28. [ ] Unlink from the Account tab. Expected: the picture disappears, and `avatar.png` and `avatar.key` are gone from `sdmc:/config/nx-discord-rpc/`.
29. [ ] Link an account without a custom avatar. Expected: the Account tab shows Discord's default avatar.
30. [ ] Change the avatar on Discord. Expected: the new picture shows within about a week (the next token refresh), or right away after unlinking and linking again.
31. [ ] Settings tab: turn Start at boot off, then reboot and open the app. Expected: `boot2.flag` is gone from `atmosphere/contents/4200000000D15C0D/flags/` and the app shows the not-running screen with a Start now button.
32. [ ] Press Start now. Expected: within a few seconds the app opens normally on the Status tab; Start at boot is still off in Settings.
33. [ ] Turn Start at boot on, then reboot. Expected: `boot2.flag` is back, the sysmodule runs and the app opens normally.
34. [ ] With Show paused games on, play a game, press HOME, and wait for Discord. Expected: the details read "Paused · HOME Menu". Repeat from the eShop and the Album (details "Paused · Nintendo eShop", "Paused · Album"), and the User page ("Paused · User page"). Note whether Discord hides or keeps its timer while paused (the console sends no elapsed time then): ______.
35. [ ] Return to the game. Expected: the details return to normal and the elapsed time resumes. Open the on-screen keyboard in a game. Expected: it still shows as playing.
36. [ ] Turn Show paused games off, then press HOME in a game. Expected: the game keeps showing as playing.
37. [ ] Turn Show docked or handheld on, then dock and undock the console. Expected: the details end with "Docked" or "Handheld" within a few seconds.
38. [ ] Turn Show total playtime on. Expected: the details end with a total (for example "45 min total") that matches the sum of every profile's playtime on this console for that game (sessions are counted once they end).
39. [ ] Start a game through a forwarder. Expected: its icon shows on Discord at once.
40. [ ] Play the same game on a second console. Expected: the image is reused, and the relay log shows no second upload.
41. [ ] Run a v0.3 console against the new relay. Expected: it still shows icons.
42. [ ] Run a v0.4.0 console against the current production relay (a relay older than v0.4.0, which ignores the icon hash). Expected: the icon still appears on Discord after one upload per title.
43. [ ] With the sysmodule running (it holds a `pdm:qry` session), open the console's own User page and its Play Activity. Expected: both still open and show the playtime as before.
44. [ ] Run a v0.3 console with `admin_key` set against the new relay. Expected: its icon uploads are stored but no longer attached to its presence, so Discord shows the logo or the legacy title icon. This is expected; leaving `admin_key` empty restores icons.
45. [ ] With the console off, add `hidden_titles = <id of game A>:private,<id of game B>:hide` to `config.ini`, then boot. Start game A. Expected: Discord shows "Nintendo Switch", "Playing a game", no game icon; the relay log shows no title id or icon hash for it and no icon upload. Start game B. Expected: no presence at all on Discord; the app's Status says nothing is shown.
46. [ ] Change a game's visibility from the app or the overlay while it runs (IPC SetHidden, a 1 KB HipcMapAlias buffer). Expected: the presence changes within about 1 s, `config.ini` holds the new `hidden_titles` line 2 s later, and the app reads back the same list (GetHidden).
47. [ ] Status tab while playing a game. Expected: the preview shows the game's own icon, name, details and a timer that matches Discord's. Press HOME with Show paused games on. Expected: the details read "Paused · HOME Menu" and the timer disappears from both the preview and Discord.
48. [ ] Set the running game to Playing a game (Private), then to Hidden. Expected: the preview shows the console artwork with "Nintendo Switch" / "Playing a game" and never the game's icon or name; then "Nothing is shown on Discord right now".
49. [ ] Status > Test connection on a working setup. Expected: all five steps turn green within a few seconds (GET /healthz over verified TLS from the app), and the Activity Privacy tip shows.
50. [ ] Test connection with Wi-Fi off (airplane mode). Expected: Internet connection fails at once, the other steps read Not checked, and the status page link and QR code show; the QR code opens the status page on a phone.
51. [ ] Test connection with a wrong host in `relay_url` (for example a typo in the domain), then with a self-hosted relay on a custom port or base path. Expected: Relay reachable fails with a short reason in the first case, and passes in the second.
52. [ ] Revoke the app in Discord (User Settings > Authorized Apps), wait for the Status footer to say the link is broken, then run Test connection. Expected: Discord link fails with "Link again in Account".
53. [ ] Open Settings > Hidden games and, while its list is still loading, go back and run Test connection. Expected: the test finishes after the list has loaded (they share one worker), and the app stays responsive.
54. [ ] Updater, TLS: with Check for updates on, open the app on a v0.5.0 install while a newer release exists on GitHub. Expected: within a few seconds the Status tab shows the banner "Version vX.Y.Z is available" with an Update button (GET api.github.com over verified TLS from the console). If nothing shows, run Settings > Check for updates now and note the message: ______.
55. [ ] Updater, redirect: press Update. Expected: the banner shows the download percentage, then "Update installed". The files come from github.com, which redirects to a githubusercontent.com host; if it fails, start the app with `nxlink -s` to read the "Update failed: <reason>" line (for example "redirect refused", or "invalid response" from a large GitHub head or signed URL): ______.
56. [ ] Updater, sysmodule restart: right after the update, without closing the app. Expected: `exefs.nsp` in `atmosphere/contents/4200000000D15C0D/` is the new one, the sysmodule runs again (presence back on Discord within about 10 s), and the About tab shows the new sysmodule version once the app is reopened.
57. [ ] Updater, overlay and toolbox: open the overlay. Expected: it is the new version (`nx-discord-rpc.ovl` and `toolbox.json` replaced); repeat the update with the overlay open in the background and note whether the overlay file could be replaced: ______.
58. [ ] Updater, nro swap: with the app still open, check `sdmc:/switch/nx-discord-rpc/`. Expected: `nx-discord-rpc.nro` is the old file, `nx-discord-rpc.nro.new` the new one, and `sdmc:/config/nx-discord-rpc/app.running` exists. Close the app. Expected: within about 10 s `nx-discord-rpc.nro.new` is gone, the `.nro` is the new version (About tab), `app.running` is gone, and `log.txt` says "App update installed". Note whether Horizon refused to move the `.nro` while the app was open (log "nx-discord-rpc.nro is in use"): ______.
59. [ ] Updater, stale heartbeat: stage a `.nro.new` by hand (copy any build), open the app, then hold the power button and power off. Boot again without opening the app. Expected: the `.nro` is replaced within about 20 s of boot (the old `app.running` counts as closed).
60. [ ] Updater, failures: turn Wi-Fi off during the download. Expected: "The update failed and nothing was changed"; the four installed files are unchanged and no `.new` or `.part` file is left. With a release of v0.4.0 or older as the latest (or a fork without the single files), Check for updates now says to update manually from GitHub.
61. [ ] Turn Check for updates off, reopen the app. Expected: no request to api.github.com (no banner even when a newer version exists); `sdmc:/config/nx-discord-rpc/app.ini` reads `check_updates=false`.
62. [ ] Updater, app in the background: after "Update installed", press HOME, wait 30 s, return to the app, then put the console to sleep for a minute and wake it. Expected: the app still works and the `.nro` is swapped only after the app is closed (the app keeps running at HOME, so its heartbeat continues; the sysmodule waits 20 s after a wake before looking).
63. [ ] Updater, TLS on two threads: open the Account tab (avatar download) and run Test connection while the start-up check or a download runs. Expected: all of them finish; nothing hangs.
64. [ ] French UI: set the console language to French and open the app. Expected: all tabs, dialogs and the overlay-independent screens are in French, accents render correctly in the shared font (no boxes). Set another language (for example German). Expected: the app is in English.
65. [ ] Settings > Hidden games. Expected: the installed games are listed with icons; each cycles Shown, Playing a game and Hidden through its dropdown; the Settings entry counts them ("None", "1 game", "N games"). Fill the list to 64 and set one more game. Expected: the message that 64 games at most can be set, and the selection reverts. A hidden id of a game no longer installed shows as "Not installed (<id>)" and can be set back to Shown.
66. [ ] Overlay "This game" entry, in game. Expected: pressing it cycles Shown, Playing a game, Hidden, and the presence follows within about 1 s; at the HOME Menu it reads "No game running". The app's Hidden games screen shows the same state within about 1 s.
67. [ ] Settings > Updates: Check for updates toggle and Check for updates now. Expected: the toggle persists in `app.ini` across restarts; Check for updates now shows "You have the latest version" when current, or "Update to vX.Y.Z" when newer, with a failure message when offline.
68. [ ] Updater, reopen right after the update: after "Update installed", close the app and reopen it at once (within 2 s). Expected: the Status tab says "An update is ready: close the app and wait about 10 seconds, then reopen it", with no Update button and no request to api.github.com (Settings > Check for updates now still checks, as a way out should the swap never happen). Close the app, wait about 10 seconds, reopen it. Expected: the About tab shows the new app version and no update banner.
69. [ ] Updater from the blocking screens: on an install whose app and sysmodule protocols differ (for example a v0.4.0 sysmodule with this app, or the reverse), open the app. Expected: under the protocol message, a banner with Check for updates (or, with Check for updates on, the newer version and Update). Press Update. Expected: the download percentage, then "Update installed"; after closing, waiting about 10 seconds and reopening, the tabs show. Repeat with the sysmodule stopped (turn Start at boot off and reboot): the not-running screen offers the same banner; Update installs and starts the sysmodule (no failure because there was nothing to stop), and presence comes back within about 10 s.
70. [ ] Updater, sysmodule that does not start again: if an update ever ends with "Update installed, but NX Discord RPC did not start again", note the `nxlink -s` line "the sysmodule did not start": ______. Expected: reopening the app shows the not-running screen with "An update is ready. Press Start now, then close the app, wait about 10 seconds and reopen it"; following it ends on the new version.
71. [ ] Log privacy: set a game to Playing a game and another to Hidden, and launch each. Expected: `log.txt` reads "Running title <id> (private)" and "Running title <id> (hidden)", without the game names; with private mode on, every game is logged as "(private)".
72. [ ] Test connection without the sysmodule: open the Status tab, stop the sysmodule from a homebrew process manager, then open Test connection. Expected: Relay reachable fails with "The sysmodule is not reachable. Reopen the app to see why", not with the invalid relay_url message.
